2. Prompt and solution design

(a) Design summary

Problem and users. A third-year engineering student usually cannot say which of their skills an internship posting will count. Syllabi change every few years, while job descriptions change every hiring season. Bridgr is mainly for students, who need to see their gap and a way to close it. Faculty use it to check a course against a target role, and recruiters use it to post internships that are matched to students by skill.

Input and output. The student pastes a resume or a short description of themselves, then picks a role or pastes a job description. Bridgr lists the skills the text gives evidence for and scores the match, marking each requirement matched, partial or missing. From there the student can generate a roadmap, rank internships, practise interviews and check a resume against an ATS. Faculty paste a syllabus and get an alignment score with suggestions per unit.

Prompts and steps. There are 10 prompts, one per task. The skills JSON from P1 and the requirements JSON from P2 are reused by other modules (roadmap, internship ranking, ATS check, mentor), so each step is its own call. Splitting the work also keeps each JSON schema small enough to check and lets each prompt run at its own temperature: 0.1 for scoring, 0.2 to 0.3 for extraction, 0.6 to 0.7 for the mentor chat and interview questions. The core path is P1 (extract skills), then P2 (weight the job's requirements), then P3 (score the gap). P4, P5, P7, P8 and P9 build on those outputs, P10 reads the saved profile and gap report, and P6 is the faculty tool.

Tool and model. We use Gemini 3.5 Flash through Google AI Studio's OpenAI-compatible endpoint. A Vercel serverless function makes the call, so the API key never reaches the browser. The free tier covered all our testing, the JSON mode cut down on broken output, and the OpenAI-style endpoint let one small client serve both AI Studio and the Vercel AI Gateway. When a model is busy (503) or out of quota (429), the function tries Gemini 3 Flash Preview and then Gemini 3.5 Flash Lite. If none of them answers, the app switches to an offline engine, labelled as such, that returns the same JSON shapes.

Changes since Milestone 1. In Milestone 1 we had a problem statement and one prompt idea. Since then we built and deployed the web prototype (12 modules), wrote the 10 final prompts with schemas and invalid-input rules, saved three versions of P3, and ran a 15-case test table with its outputs kept in the repository. On 24 November we moved from Gemini 2.5 Flash to Gemini 3.5 Flash, because Google no longer gives 2.5 Flash to new API keys.

P3 · Skill Gap Mapper

Step in the workflowStep 3: Compare student vs industry (core)
PurposeCompare the structured student profile with role requirements and produce a scored, explainable gap map.
Tool and modelGemini 3.5 Flash in Google AI Studio (OpenAI-compatible endpoint), called from a Vercel function; fallbacks Gemini 3 Flash Preview, then Gemini 3.5 Flash Lite
Settingstemperature 0.1; response_format json_object; 2 attempts per model
Full system prompt
You are a fair, strict career assessor. Compare a student's skills with a role's requirements. Treat obvious synonyms as the same skill (JS = JavaScript, ML = Machine Learning, Postgres = SQL). Rules: matched = student level >= required_level; partial = student has it but below required_level; missing = not present. match_score = round(100 * sum(weight*min(student_level/required_level,1)) / sum(weight)) over must_have and good_to_have (good_to_have weights halved). Be honest — do not inflate scores. Respond with ONE valid JSON object only. No markdown, no code fences, no commentary. If the input is empty, meaningless or unrelated to careers/education, return {"error":"invalid_input","message":"<short reason>"}.
Full user prompt template
STUDENT SKILLS (JSON):
{student_skills}

ROLE REQUIREMENTS (JSON):
{role_requirements}

Return JSON:
{"match_score":0-100,"readiness":"Not ready|Developing|Almost ready|Ready","matched":[{"skill":string,"student_level":number,"required_level":number}],"partial":[{"skill":string,"student_level":number,"required_level":number,"gap":number}],"missing":[{"skill":string,"required_level":number,"priority":"High|Medium|Low","why_it_matters":string}],"strengths":[string],"verdict":string}

3. Implementation

Bridgr is a single-page web app in vanilla JavaScript with Chart.js and a hash router, hosted on Vercel. Every AI feature sends POST /api/ai {promptId, vars} to one serverless function. It fills the prompt template, calls Gemini in JSON mode, parses the reply (trying again if parsing or the call fails) and returns {ok, data, model, ms}. Profiles, gap reports, roadmaps, applications and a log of every AI call are kept in the browser's localStorage, which is why there is no login. Scripts in code/scripts/ run the test table and the prompt-version experiment against the API and save the outputs.

6. Supporting document

Type: Synopsis. The same document is uploaded at Q16 as PromptBusters_Synopsis.pdf.

Bridgr: AI-powered academia-industry skill mapping and internship portal

Synopsis · SCSE4041 Mini Project, Milestone 2 · Team Prompt Busters (PE-B65-43)

Problem

An engineering student can finish three years of coursework and still not know which of those skills an internship posting will count. Syllabi change every few years, while job descriptions change every hiring season. Students guess what to learn next, faculty seldom see what employers ask for, and recruiters screen applicants whose skills do not fit the role.

Objectives

  1. Read a student's resume or self-description and list only the skills it gives evidence for, each rated from 1 to 5.
  2. Compare that list with a real job description and produce a match score the student can check by hand, with each requirement marked matched, partial or missing.
  3. Help close the gap with a week-by-week learning plan, mock interviews scored against a rubric, an ATS resume check and a mentor chat that knows the student's profile.
  4. Let faculty test a syllabus against a target role and see which topics are outdated and which units need new material.
  5. Link the result to internships: rank openings by fit, apply in one click and track each application.

Scope

Bridgr is built for undergraduate engineering students in India who are looking for internships, and for the faculty and recruiters around them. The Milestone 2 prototype is a web app with 12 modules. It needs no login and keeps all data in the browser. Internship listings are sample data. Accounts, live job feeds and a mobile app are outside the current scope.

Methodology

The work is split into ten prompts (P1 to P10), one per task. The skill list from P1 and the job requirements from P2 feed several later modules, so each step returns its own JSON that the app can store and reuse. Each prompt has a fixed role, explicit rules, a JSON schema, a temperature chosen for the task (0.1 for scoring, higher for the mentor chat) and a rule that returns {"error":"invalid_input"} for empty or unrelated text. The core path is P1 (extract skills), P2 (weight the job's requirements) and P3 (score the gap).

The browser app (vanilla JavaScript and Chart.js) sends each request to a Vercel serverless function, which calls Gemini 3.5 Flash through Google AI Studio in JSON mode. If that model is busy or out of quota, the function tries Gemini 3 Flash Preview and then Gemini 3.5 Flash Lite. If no model answers, a labelled offline engine returns the same JSON shapes so the interface keeps working.

The Skill Gap prompt (P3) went through three versions. Version 1 was a one-line request at temperature 1. Version 2 added a role and a JSON shape. Version 3 added scoring rules, synonym handling, a weighted formula, one worked example and temperature 0.1. Fifteen test cases covering normal, edge and invalid inputs run by script against the API, and their outputs are saved in the repository.

Results so far

Fourteen of the 15 test cases pass. The failure is the curriculum auditor (P6), which scored a DBMS syllabus at 62 when we expected 30 to 60. In three runs of each P3 version on Gemini 3 Flash Preview, version 1 never returned valid JSON. Version 2 returned JSON every time with a score of 50, but it called SQL and Excel "matched" while its own verdict said both were below the required level. Version 3 returned JSON every time with a score of 54, which is what its formula gives when worked by hand (100 × 10 ÷ 18.5 = 54.05).

Expected outcome

A student pastes a resume, picks a role and gets a score with the reasons behind it, a short list of what to learn and internships ranked by fit. Faculty get a unit-by-unit list of syllabus changes. For Milestone 3 the team plans to pilot Bridgr with students and faculty, add accounts with cloud sync, and connect live internship listings.
